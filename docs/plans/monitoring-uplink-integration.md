# GTSWN 监测体系与上行优化整合实施计划

> 状态：计划已成稿；本文不代表代码已经实现、测试通过或 PR 已创建。
> 执行原则：先保存 Markdown 并归档至 Space，再依序实施；执行产物通过相关仓库 PR 交付，不直接推送目标分支，不合并 main。

## 1. 目标与边界

把监测体系重构和服务端向客户端的数据同步优化作为**同一项工程**实施。
每个纵向切片同时交付数据源身份、服务端模型、订阅、线协议、客户端消费、迁移和测试，
不先在旧模型上完成一轮网络优化，再重做一轮新监测体系。

- GTSWN 静态基线：`89c59d3bcde081bc0940381f60209cad053d9fca`，版本 `v2.0.25`。
- 集成与兼容以 RC2 为执行基线；RC1 仅作静态对照，不作为运行验收环境。
- 保持 Java 8 字节码兼容；复用现有 MIAOKATZE-Core 能力，不另造通用监控大框架。
- 范围包括 EU、便携监测器、AE、DIT、工程桌面和量子监测的身份、历史、订阅与同步。
- Web 仅为同一授权快照的可选只读适配器，不成为第二套采样与权限系统。
- “上行优化”在本文主要指服务端→客户端状态同步，同时约束反向请求、ACK 与续租。
- 不改生产网络暴露，不提交认证秘密，不擅自进入世界或开展游戏内运行验证。

## 2. 已知现状：保留有效机制，解决真正重复

以下为基线代码静态观察，不是实测带宽、TPS 或性能收益。

| 链路 | 基线观察 | 本次对应处理 |
| --- | --- | --- |
| 便携监测 | 最多四组、每组 61 个 double 的历史，数组负载约 1956 B；已知渲染缓存命中仍可能传历史 | 配置版本与采样版本分离；原始历史按有界尾部传输 |
| 实体 EU | 已有单采样增量、约每 8 次增量后的全量恢复；静态 NBT 仍重复 | 保留增量与恢复机制，把静态配置独立出去 |
| AE | 64 格内实体屏幕属于有效观察入口 | 纳入可见观察租约并设置宽限，不因没有 GUI 就误判无人观看 |
| DIT | 已有完整 ACK、冻结分页、版本 keepalive；新版本仍发送全行，固定字段约 60 B 加 5 个字符串 | 延用完整基线协议，在已确认版本上增加字段增量 |
| 工程桌面 | 约 1 Hz 全量快照；link 节点约 20 B、quantum 节点约 33 B 的字段在对应类型下固定为零（不是整个节点大小） | 元数据独立、节点类型明确、按订阅字段发送 |

计数口径须区分应用负载、序列化开销、包头和实际发送次数；禁止凭静态字节数承诺节省比例。

## 3. 最小统一模型

### 3.1 SourceKey：识别真实数据源，而非识别显示道具

- `SourceKey` 由源类型、真实原生身份、世界 epoch 和 generation 组成；具体编码按源适配。
- 坐标只作定位信息，不能单独证明“仍是原来那个设备”；同坐标替换必须切换 generation。
- EU 应对应真实电网或账户身份；AE 对应实际网络身份；DIT 对应真实被监测设备身份。
- 网络分裂、合并、替换或不可证明身份连续时，产生明确边界，不盲目拼接历史。
- 世界重载、恢复旧存档、跨世界复制等情况须检测 epoch／revision 失配并重建同步基线。
- 客户端不能自报可信 SourceKey 获得权限；服务端必须验证绑定与访问权。

### 3.2 MonitorProfile：可恢复的服务端档案

- `MonitorProfile` 保存档案 ID、所有者、ACL、源引用、显示配置、历史引用及迁移版本。
- 档案落在服务端持久存储；道具、实体屏幕、工程桌面只持有引用，不决定档案寿命。
- 丢失道具、退出 GUI、退出游戏、实体卸载，不隐式删除档案及历史。
- 提供按权限恢复引用的入口；档案删除与历史清理由显式规则决定，而不是“当前没有道具”。
- ACL 与所有权持久化，读取、订阅、修改、转移分别检查，管理员权限也应有明确入口。
- 转移由服务端执行并使旧授权缓存失效；持有复制道具不等于获得档案所有权。
- 旧道具 UUID 只作为迁移线索；复制 UUID 必须幂等解析，拒绝越权认领，禁止重复建档。
- 原有历史保留原归属与来源信息；只在身份得到证明时关联，不静默吞并或清空旧历史。

### 3.3 共享采样与可见性

- 复用现有 scheduler、DataStore、controller 和 collector，增加轻量源适配层即可。
- 同源同周期只采样一次，再按订阅投影；相同 SourceKey 不因多窗口、多道具或 Web 重采。
- 仍需每 tick 记账的 watched-tick／流量统计继续保留；低频发包不等于低频记账。
- 不声称所有源都能统一采样周期、单位、可用性或完整性；不支持的能力明确返回状态。
- 区块未加载、网络不可达或身份失效时只提供最后快照和原因，不强加载区块。

## 4. 订阅、离线作业与客户端状态

- 在线观察采用短租约：开界面、有效屏幕观察、工程窗口等入口续租，关闭或超时自然释放。
- 租约不是 ACL；每次建立、续期和权限变化均经过服务端授权。
- AE 实体屏幕的有效范围观察保留宽限，避免边缘移动与短暂遮挡导致频繁停采／全量重传。
- 离线持续采样必须创建**显式、持久化、受配额限制的作业**，不把在线租约无限续期。
- 作业记录 owner、SourceKey、所需能力、频率、保留期、配额与暂停原因；重启可恢复。
- 在线观察与离线作业共享采样结果；最后一个在线观察离开不取消仍有效的离线作业。
- 离线作业不强加载区块；源不可用时记录缺口或暂停，不把旧值当成新采样。
- 客户端只渲染已经授权的缓存快照，不在渲染路径读取世界或发起无界查询。
- 状态至少区分：实时、缓存／过期、等待同步、源未加载、无权限、源已替换、作业暂停。
- 展示采样时间与数据完整性；“无数据”和数值零分开，权限撤销时移除敏感缓存。

## 5. 同步协议：与模型一起落地

### 5.1 配置、元数据、状态、历史分层

- 配置／元数据仅在其 revision 变化时发送；新采样不再使配置缓存一并失效。
- 最新状态可合并；历史使用有界原始尾部、序号与缺口标记，必要时请求受限全量。
- 客户端基于原始历史重新计算归一化图形；不能简单追加旧归一化点，造成缩放尺度不一致。
- 数据源类型决定合法字段；量子节点不再为了复用布局而发送没有语义的固定零字段。
- 订阅声明实际需要的字段、窗口和历史范围，服务端裁剪后发送，不能让客户端扩张读取权限。

### 5.2 可验证的增量基线

- 增量只基于**客户端已 ACK 的完整基线**；“已发送”或“收到部分分页”不能作为 ACK。
- 包含协议版本、SourceKey／档案引用、epoch、base revision、target revision 和消息类型。
- 明确定义新增、修改、删除、空集合、reset；不能只补新增项而留下被删除的旧数据。
- 失配、断线重连、乱序、重复、丢包、回滚或分页中断进入有界 reset／全量恢复。
- DIT 保留冻结分页、完整 ACK、keepalive；在此之上增加字段掩码与字典／元数据版本。
- ACK 处理校验玩家、会话、源与版本，不能以伪造 ACK 跳过授权或推进无效基线。

### 5.3 有界发送与兼容

- 每玩家与全局都设字节预算；另设消息长度、行数、历史点数、排队数和重同步频率上限。
- 最新状态允许合并成最新一份；控制消息、确认、授权撤销和迁移结果保留 FIFO 语义。
- 拥塞优先降低非关键状态刷新，标记延迟；不悄悄丢弃控制消息或制造历史连续的假象。
- 所有解码入口防御负数、越界长度、截断、未知枚举、无效 revision 与压缩后膨胀风险。
- 保留已有 packet discriminator，不重排复用；新增协议明确协商能力，拒绝无协商改旧包布局。
- 不支持新协议时走已声明的旧路径，或给出清晰不兼容提示；不能让混合版本静默错解。

## 6. Web：最后接入的只读适配器

- 默认关闭；只有 OP／服务端管理员可开启全局开关，档案所有者仍须单独 opt-in。
- 首版默认全服最多启用 1 个 Web 仪表盘，可配置多个；访问者并发与总发送字节另设配额，不能把仪表盘数误当访问人数。
- 仅允许导入已授权的固定源引用；导入到独立 ghost／虚拟视图，不生成伪道具或伪 ItemStack。
- 固定源变更必须重新授权，不能以自由坐标、网络 ID 或任意查询变成全服扫描接口。
- 使用独立端口、TLS 和认证；凭据不入仓库、不入默认配置、不在 URL 与日志中泄露。
- 首版只读：不提供设备控制、所有权转移、任意命令或外部修改档案接口。
- HTTP 线程只读已授权的不可变缓存快照；不读取 World、不访问 TileEntity、不触发采样。
- HTTP 请求、响应字节、会话、查询窗口和缓存均有预算；断开后释放短租约。
- 服务关闭、认证失效、owner 撤销授权时立即停止访问；错误页不泄露源信息与内部路径。
- 本次可实现并验证适配器，但不开生产监听，不替用户申请域名、证书或配置公网转发。

## 7. 纵向切片与 PR 顺序

每个切片均覆盖“源／模型 + 订阅 + 线协议／客户端 + 测试 + 迁移”；一个切片可拆为多个小型 PR，未改动的层须明确兼容契约。
首批闭环：便携监测的来源一致缓存与兼容式曲线复用，并同步修复服务端换世界／回退时钟与佩戴终端的活跃登记边界。这不等于完整服务端档案、Web 或全部增量协议已交付。
底层公共代码只为本切片的真实闭环服务，不先搭一套尚无使用者的大框架。
首批可从便携快照复用与源生命周期保护切入，但必须说明其对应的新模型契约与阶段边界，不能据此宣称全计划完成。

### 切片 1：身份与协议契约 + 有界可观测性

- 先以现有来源身份与会话机制建立契约；在持久档案实际接入时引入最小 SourceKey、MonitorProfile 引用，不提前堆积无人使用的类。
- 以一个真实现有源打通授权订阅、协商、完整快照、客户端缓存及旧绑定读取。
- 在现有发送／采样入口记录负载字节、采样次数、缓存命中、reset 与队列占用；日志限频。
- 加入基线 ACK、预算、迁移幂等的模型测试；旧行为默认保持，避免只交付空接口。

### 切片 2：EU／便携／AE 共享采样 + 配置与历史拆分

- 将实体与便携的相同源映射为共享采样，接入 profile 引用；保留 watched-tick 记账。
- 同切片迁移原配置与历史引用，保留旧读取，明确原记录到新 SourceKey 的映射依据。
- 订阅覆盖 GUI、便携与 AE 实体屏幕观察；实现宽限与租约释放。
- 同时交付配置 revision、原始历史尾部、客户端归一化重算及全量恢复。
- 测试同源多消费者只采一次、未知身份不合并、断点历史和复制 UUID 的幂等迁移。

### 切片 3：DIT 档案与字段增量

- DIT 从道具生命周期改为可恢复 profile，补齐 ACL、显式转移与历史来源保留。
- 复用现有请求队列、冻结分页、完整 ACK 与 keepalive；增加字段增量、删除与 reset。
- 客户端只在整版本完成后提交基线；分页期间不把部分新数据拼成已完成版本。
- 一并测试重新取得终端引用、复制 UUID、权限撤销、分页中断和版本回滚。

### 切片 4：工程／量子元数据、节点类型与字段订阅

- 工程桌面绑定统一源引用；复用已有 collector，按必要字段组织共享快照。
- 静态名称／位置／拓扑元数据独立版本化；节点 kind 决定字段，删除固定零占位。
- 同步实施类型化 wire、客户端增删改缓存与旧桌面绑定迁移，保留截断／不可用提示。
- 优先实际活跃工程快照与 Lite 路径；未使用 full 路径只做必要兼容整理。

### 切片 5：离线作业、恢复 UI 与 Web 只读适配

- 在已完成的源和协议上增加持久化离线作业、配额、暂停／恢复及无强加载保证。
- UI 提供档案恢复、明确状态、owner opt-in 和撤销；授权变化与缓存清理同步完成。
- Web 只消费同一快照，完成关闭默认值、仪表盘数量上限与独立并发配额、ghost 导入、认证与预算边界。
- 用模型／适配器测试验证线程边界、无世界读取、拒绝越权和关闭时零监听行为。

### 切片 6：兼容回归、迁移收口与分阶段启用

- 汇总跨源复用、重启持久化、ACL、旧格式与混合协议的回归结果。
- 执行允许范围内的编译、打包和启动／退出冒烟，修复失败后重新验证。
- 列出仍需另行授权的世界内场景；未执行的验收明确标记，不以单元测试替代。
- 补齐配置说明、迁移说明、回滚步骤和全部已实现变更；按依赖顺序提交小型 Draft PR。

## 8. 新配置建议（不是现有配置声明）

| 建议项 | 初始原则 |

## 9. 验收矩阵与验证权限

| 主题 | 必须满足 | 本轮可用证据 |
| --- | --- | --- |
| 身份／持久化 | 同源共享；替换隔离；复制 UUID 幂等；旧历史不丢 | 纯模型、序列化及迁移样例测试 |
| ACL／转移 | 未授权拒绝；转移后旧授权失效；持久化恢复一致 | 权限状态机与存储测试 |
| 采样／观察 | 租约到期停止；离线作业独立；记账不丢；不强加载 | 调度器与源适配替身测试 |
| 协议／缓存 | 完整 ACK 基线；增删改／reset；断包与回滚安全 | 编解码、乱序／丢包与客户端模型测试 |
| 历史／图表 | 原始尾部有界；缺口明确；归一化重算正确 | 数值与窗口测试 |
| 预算／Web | 双层预算；控制 FIFO；默认关闭；HTTP 无世界读取 | 队列、授权及只读适配器测试／静态边界检查 |
| Java／发布 | Java 8 字节码；RC2 兼容；Core 复用 | 编译、打包、依赖与字节码检查 |
| 启停 | 服务端可启动并停止；客户端到主菜单后退出 | 受限冒烟日志；客户端不进入存档，专用服务端仅初始化隔离测试世界并正常停止 |

禁止未经另行授权开展额外世界内功能场景、客户端进入存档、玩家操作、长时压测或真实生产网络测试。
编译通过、服务器启停或客户端主菜单成功，均不能表述为“世界内功能已验证”或“性能已提升”。

## 10. 风险与回滚

- 身份误合并：优先隔离并提示重新绑定；不自动合并不能证明连续性的历史。
- 迁移中断：保存迁移标记与映射，使用可重复执行步骤；旧记录在明确收口前不删除。
- 存档回滚：epoch／revision 不一致即 reset；不将新缓存覆盖旧存档的真实状态。
- 协议混用：保留 discriminator 与能力协商；不支持时按已声明策略降级／拒绝。
- 预算过紧：显示缓存／延迟状态并调整配置，不通过无界队列掩盖拥塞。
- 新路径故障：按源／切片关闭新路径，回到保留的旧同步；禁用 Web 独立生效。
- 数据降级：新档案不可逆格式不得悄悄写入旧字段；回滚使用备份与兼容读取说明。
- 删除旧代码／旧数据必须另有明确迁移完成证据；“新路径能跑”不是清理旧历史的依据。
