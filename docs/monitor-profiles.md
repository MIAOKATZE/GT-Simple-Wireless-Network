# 服务端监测档案、恢复与显式作业

本说明对应新增生产代码；编译、单测及运行证据由交付记录单独列出，不等于已经完成世界内功能验收。

## 玩家入口

普通玩家使用 `/monitorprofile`（另有档案 GUI 入口，见命令帮助）：

- `import` / `create`：检查**当前实际手持**终端并明确创建档案。支持 DIT、已初始化便携监测器、已通过原生配对与权限检查的量子终端。
- `list` / `status <档案 UUID>`：列出自己拥有／获分享的档案及可用状态、最后采样 tick、作业信息。
- `recover <档案 UUID>`：把新终端绑定到已有档案，不再复制历史。DIT 需手持 DIT，便携档案需手持便携监测器；量子终端必须先按原生流程重新获得同源合法配对，档案不会制造加密凭据。
- `release <档案 UUID>`：仅 owner 手持当前对应的量子档案终端时可用，解除这一件物品的档案引用和导入标识；保留原生配对信息、服务端旧迁移映射、旧档案、历史、ACL 与其他物品副本。控制器迁移或结构拆分／合并导致固定来源失效时，先解除这一件物品，再按原生流程重新配对，并明确导入为新固定来源档案。不会自动扩展旧 Web 同意。
- `share <档案 UUID> <玩家 UUID>` / `revoke ...`：owner 授予／撤销只读 ACL；读者不能修改配置或转移所有权。
- `transfer <档案 UUID> <玩家 UUID>`：新 owner 必须已具备当前原生源权限。转移清空旧 ACL，并关闭离线作业和 Web consent。
- `offline <档案 UUID> on|off`：明确创建／停止持久化采样意图；不因拿过终端或打开过界面自动创建。
- `web <档案 UUID> on|off`：owner **同意／撤销固定来源的 Web 导入**，不是建立仪表盘或打开端口。OP 还需通过 Web 注册表明确创建页面；页面对服务器配置的 bearer-token 访问者可见，不限于游戏档案 ACL 读者。Web consent、页面配置、采样作业彼此独立。
- `detach <档案 UUID> <来源定位字符串>`：owner 显式移除档案来源。DIT 定位形如 `0:1:64:2`；便携来源以服务端列表中的固定定位引用为准。

导入后来源集合是固定的：自动放置绑定、扫描和直接右击添加不会偷偷扩大可共享的档案。EU-only 档案屏幕后续出现 AE 连接／配置／缓存时会标记来源已替换；有残留 AE 数据的未通电屏幕不能当成纯 EU 导入，需要恢复原生 AE 后明确导入新档案。
要监测新的来源，使用传统终端准备绑定后明确导入新档案；也可以从档案移除来源。

## 历史与旧物品

- 传统 UUID 继续采用原来的 bearer 访问规则。拿到复制旧终端不等于得到新档案所有权。
- DIT 明确导入时**一次性复制**原绑定、历史及显示配置到新的档案 UUID；旧 UUID 与旧数据独立保留。
- 旧 UUID → 档案 UUID 映射持久化；重复导入同一旧 UUID 不重复建档，换一个持有者不能据此认领原档案。
- 档案引用恢复只改当前服务器手持物品，不复制历史、不删除原物品所引用的数据。
- 私有 DIT 数据还持久化 `monitorProfile` 标志；丢失／损坏档案元数据不会把它降级为公共旧 bearer 数据。
- 原生设备拆除／替换不会隐式删除已导入的 DIT 历史。明确解除绑定会移除该档案的对应记录。
- EU 使用实际 GT 无线账户 leader 作为原生身份，团队变化会形成边界；旧 owner-key 历史保留为归档，不与新账户拼接。
- AE 使用注册到 AE 原生 grid cache 的监测 UUID，并通过 `IGridStorage` 保存／恢复，不使用会话随机的 `IGrid.getId()`。同一 grid 的多个屏幕共享源身份与当前采样，但每块屏幕的选定条目历史仍按屏幕与来源分别保存。正常重建拟保留可证明连续的原生身份；拓扑启动期间不发布身份，已发布网络拆分、不同已知网络合并或身份无法证明时建立新边界。旧 coordinate／旧代历史保留，不自动拼接。真实旧存档与网络重建验收尚需按验证清单执行。
- 量子原生系统继续按控制器注册结构管理网络，既有节点归属、配对、调色与网络安全规则不改成玩家级网络。新增档案是持有固定来源引用、ACL、离线意图与发布同意的监测层，不是量子网络数据库的替代品。当前量子来源标识包含控制器原生代次、安全身份及成员集合边界；玩家 UUID 用于授权，不用于代替该网络标识。

## 权限与身份

- 客户端提交的 UUID、坐标或 SourceKey 均不是授权；服务器检查物品、ACL、固定绑定与当前原生来源。
- DIT 源包含世界 epoch 与原生安装 UUID。安装 UUID 存在真实 TileEntity mixin 的持久化标记以及登记表中；真实放置强制生成新代，同坐标同类型替换也不会续接旧源。
- DIT 导入要求当前 loaded 工作机器的真实 GT owner 与玩家一致，不把旧登记表的点击者当作原生所有权证明。
- AE 导入要求真实屏幕身份／owner，且当前原生 security provider 授予 SECURITY（或原生 owner）；没有 security provider 时仍检查真实屏幕 node 所属玩家。不是“拥有某块面板就扫描任意全服 AE 网”。
- 量子作业遵守档案保存的间隔，并报告共享 collector 的真实采样 tick，不能把读取缓存的时间冒充新采样。
- 量子原生授权由 `QuantumProfileAdapter` 校验，不向档案、Web DTO 或日志复制加密 key。
- ACL、转移、来源失效会撤销服务器排队的 DIT／便携快照与 Web 缓存；旧协议使用真实单调版本的空快照清理，绝不写入 MAX_VALUE 毒化基线。
- AE／量子来源不可用且无法复核原生安全状态时，敏感缓存拒绝发布；不把旧值当作新的授权或采样。

## 作业边界与配额

当前为明确的代码硬上限，不伪装成已有配置项：

| 项目 | 上限 |
| --- | ---: |
| 档案总数／每 owner | 4096 / 32 |
| 每档案读者／来源 | 64 / 512 |
| 启用作业总数／每 owner | 64 / 4 |
| 启用作业聚合唯一 SourceKey（全服／每 owner） | 4096 / 1024（给原有 flow monitor 留容量） |
| DIT 原始双通道环历史 | 每通道 60 点 |
| Web 单来源投影 | 有界卡片与原始历史尾部，详见 Web 文档 |

- DIT 沿用现有采样调度器：同坐标工作队列去重，在线与离线消费者共享一次采样。
- EU 沿用公共监控控制 API 与原生账户采样锁；AE 续租独立 job interest，沿用原有控制器采样周期。不是另起一套采样器。
- EU/AE 周期遵循各自原有源能力（EU 原生 100 tick，AE 原生配置周期）；不能把订阅刷新频率说成真实采样频率。
- 持久化的是 owner、固定来源、频率／配额与启用意图，不持久化 EntityPlayer、World、TileEntity 或活跃租约。
- 重启恢复意图后重新检查 native 权限与来源身份；不能证明连续性就暂停／显示来源已替换，不强行恢复旧基线。
- 只使用已加载维度／区块，不调用 `initDimension`，也不申请强制加载。不可用有缺口／暂停状态，没有伪造零值。
- Web raw history 中非有限值用缺口表示；`unknown` 与数值零严格区分。

## 回滚

关闭 Web、关闭显式离线作业即可停止新增相关流量。传统终端及旧数据不删除。
退回不支持档案 ACL 的旧版本前，必须保留世界备份并移走／禁用新档案引用物品：旧版本不会理解新 ACL，不能把“旧版本能读 NBT”当作私有数据安全兼容。
